# Android app

One Android `app` module hosts the React Native companion in `../src/mobile/`. Kotlin owns the connection, security, pairing, notifications, device setup and terminal views. Read `../src/mobile/AGENTS.md` before changing that boundary. Keep [`README.md`](README.md) current when its described behavior changes.

## Commands

Install root npm dependencies and run `node tools/android-companion-tools.mjs` from the repository root before Gradle. Run these commands from `android/` with JDK 21. The SDK path comes from `ANDROID_HOME` or the ignored `local.properties` (`sdk.dir=...`).

| Task | Command |
| --- | --- |
| Unit tests | `./gradlew testDebugUnitTest` |
| Lint; any error fails | `./gradlew lintDebug` |
| Build a debug APK | `./gradlew assembleDebug` |
| Release APK (R8) | `./gradlew assembleRelease` |

CI's `android` job runs `testDebugUnitTest lintDebug` and `assembleRelease`; run the same before a PR. Its path filter includes native, React Native, relevant shared/client sources and root dependency/build inputs. Root `npm run typecheck` includes mobile TypeScript, not Kotlin. Debug builds use Metro (`npm run mobile:start` from the root); release builds bundle JavaScript. Install with `adb -s <serial>` on an explicitly authorized target.

## The office is the contract

- The app speaks the office's WebSocket protocol (`src/shared/protocol.ts`) and HTTP routes (`src/server/server.ts`). `core/Protocol.kt` mirrors the messages the app uses; when the server adds or renames a field the app reads, update it and `ProtocolTest`. Unknown fields and messages are ignored (`ignoreUnknownKeys`), so an older app keeps working against a newer office.
- Pairing (`droidoffice://pair` links, `/api/mobile/pair`, `/api/mobile/hello`, device tokens, close code `4401`) is described in [docs/guide/android.md "Droid Office for Android"](../docs/guide/android.md). `core/Pairing.kt` must keep parsing every link the office can print, including the plain join URL with `?t=`.
- An office from before phone pairing has no `/api/mobile/*`: the app falls back to the LAN token. Keep that path working.

## Code

- `core/` is pure Kotlin with no Android imports, so its JUnit tests run on the JVM. Put logic there (parsing, ordering, labels, the terminal model) and keep `ui/` to layout and state wiring.
- The terminal is xterm.js in a WebView: the page is `app/src/main/assets/terminal/`, talking to `ui/worker/TerminalPage.kt` through the messages in `core/TermPage.kt`. Its DOM-free logic lives in `input.js` and is tested by `tests/android-terminal.test.ts` in the root `npm test`, which also checks `theme.js` against the office's terminal colours. Never edit `terminal/vendor/`: it is written by `node tools/android-terminal.mjs`. The page loads nothing from the network and never forwards xterm's own `onData`: the PTY's answers to queries already come from the office's terminal.
- A Whiteboard card opens live in a WebView: the page is `app/src/main/assets/whiteboard/`, talking to `ui/board/CardPage.kt` through the routes and messages in `core/WbPage.kt`. It frames the card with the office's `CARD_SANDBOX` and `CARD_ALLOW` and speaks the window's bridge (`src/shared/whiteboard-bridge.ts`); the app listens to that page's origin only, never to the card's frame. Its DOM-free logic lives in `marks.js` and is checked against the office's reducer and marks code by `tests/android-whiteboard.test.ts`. When the window's surface or bridge changes, change the page with it.
- Do not add a companion 3D map or renderer. Wide screens use the shared roster and up to four worker panes; preserve the separate first-person desktop office.
- Shared management windows run in bundled `app/src/main/assets/companion-tools/`, generated by `node tools/android-companion-tools.mjs`. Change their TypeScript source, rebuild and commit generated assets. Native validates the shared HTTP policy before adding authentication. Accept privileged messages only from the local host's main frame through an origin-restricted listener, never a Whiteboard child frame or unrestricted `addJavascriptInterface`.
- One `OfficeConnection` owns the socket for the current office. Screens and services `hold(tag)` and `release(tag)` it rather than opening their own.
- Preserve monotonic message sequence and socket epoch ordering through bootstrap and warm reconnects. A connected link is not authoritative until welcome/floor arrival. Terminal subscriptions are reference-counted; only an active, ready, laid-out terminal may type or resize.
- Floor navigation keeps per-floor drafts and pictures in memory. Actual connection loss discards them across all floors, including unmounted panes and management tools. Persist layout only; never replay actions or unconfirmed Whiteboard mutations. Submitted Droid queue entries are not unsent drafts.
- Tokens only ever go through `TokenVault`. Never log a token, a pairing link or a request URL that carries `t=` or `d=`.
- Plain HTTP and `ws://` are allowed only to private addresses, enforced by `net/CleartextGuard.kt` on the address actually connected. Every OkHttp client gets it as a network interceptor.
- Colours, type and shapes come from `ui/theme/` (the office's dark palette and Factory orange, Geist and Geist Mono). Icons are vector paths in `ui/theme/OfficeIcons.kt`; add one there instead of pulling in a larger icon library.
- Strings a user sees are plain sentences in the office's voice, matching the web client.
- Give React Native controls stable `testID`, accessible labels and states. Native Compose setup controls use `core/Tags.kt` and `Modifier.tagged(...)`; do not reuse identifiers for different actions. A native toggle row is `toggleable` with its `Switch` given `onCheckedChange = null`, and a choice is `selectable`, so a dump reports it as `checked`.
- Never move a node's bounds every frame (a rotating `graphicsLayer`, an animated offset or size) on something that loops forever: the accessibility events it sends keep `uiautomator dump` from idling. Animate in the draw phase instead.
- Fix what lint reports. Don't add `@SuppressLint` or widen `lint { disable }` to pass; the ones disabled there only flag that newer library versions exist.
- Bump a library in `gradle/libs.versions.toml`. Updating Gradle itself also updates `distributionSha256Sum` in `gradle/wrapper/gradle-wrapper.properties`.
- `react-native-plugin/` builds the pinned npm React Native Gradle plugin sources with this app's Kotlin and AGP versions. Keep those sources in root `node_modules`; do not copy or patch vendored plugin code to fix a toolchain mismatch.
