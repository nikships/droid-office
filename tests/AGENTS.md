# Tests

- Flat files named `tests/<name>.test.ts`. `npm test` is `node --import tsx --test --test-timeout=120000 tests/*.test.ts`; a test still running after two minutes fails by name, and a file in a subdirectory never runs.
- `node:test` and `node:assert/strict`. Import the source by its `.js` path (`../src/server/workers.js`, `../src/client/world/gun.js`); tsx resolves it. A client module that touches `window`, `document` or WebGL at import time cannot load this way.
- `npm run test:coverage` (Node 22.8+) is what CI runs. Its line and function floors are the `--test-coverage-lines` and `--test-coverage-functions` flags in the `package.json` script, with `tests/**` outside the denominator. When a change to `src/` or `bin/` drops either number, add coverage until the command passes. Lower a floor only to the number the suite actually holds, in the same change.
- `tests/env-example.test.ts` fails when a `process.env` read or a `DROID_OFFICE_*` name in `src/` or `bin/` is missing from `.env.example`. The names it skips are listed in it.
- A test that drives a fake clock while the code under test does real async work (file reads, fake commands or fetches) waits until that work is done before it moves the clock or asserts, never for a fixed stretch of real time; the rig in `tests/subscriptions-state.test.ts` does this. Before shipping one, add a random real delay to its fakes and run the file many times at once: it passes on a slow CI runner only if it passes that.
- Fixtures live under `os.tmpdir()` and go with `t.after`. A test that needs git, `gh` or a provider CLI stubs the binary, and stays off the network and out of this checkout's `.droid-office/`.
- Stubs exist only because CI has no keys or sign-ins. Copy every stubbed answer (a Factory or forge API body, a CLI's output) from a real one read from the owner's account, trimmed and with secrets replaced. A change the running office shows still gets the running-office check in the root [AGENTS.md](../AGENTS.md) "Testing the running office".
