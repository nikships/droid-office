# Desktop

Electron's main process for the Mac app. The office the window shows is the Vite client, not this directory.

Read [presenter.md](presenter.md) before changing input, the presenter window, the page shim, DevTools Protocol attachment, crash or paint-stall recovery, or any presenter timer or listener.

- `tsconfig.desktop.json` typechecks this directory (Node types, no DOM) and emits `dist/desktop`. Relative imports end in `.js`. `package.json` `"main"` is `dist/desktop/main.js`.
- The window loads the office page with `sandbox: true` and `contextIsolation: true`. Office UI stays in `src/client`.
- `app.setPath('userData', …/com.nikships.droid-office)`. The default `Droid Office` folder belongs to the Unity office.
- `office.ts` starts `bin/droid-office.js` on Electron's Helper binary (`runtime.ts`) with `ELECTRON_RUN_AS_NODE=1`, in the login shell's environment (`shell-path.ts`), not just its `PATH`. Quitting sends that process SIGTERM, which keeps workers and PTYs. A script the office itself runs with `process.execPath` still goes through `runAsNode` in `src/server/workers.ts`.
- Closing the window, Cmd+Q included (**Close to Menu Bar**), leaves the app running as a menu bar icon (`tray.ts`; the pure menu, its status lines and what each state allows are `tray-model.ts`, tested in `tests/desktop-tray.test.ts`). `main.ts` hides the Dock icon then, and `windowWanted` keeps a restart or a crash from opening the window again. Only `before-quit` stops the office, and every real quit comes through it (the menu bar's Quit, Option+Cmd+Q, the Dock, logout, shutdown, an update); each of those stays a quit. `tray-icon.ts` is written by `tools/tray-icon.py`: run that rather than editing it.
- The app has exactly one window, in one of two modes, `settings.mode` (`office`: the presenter; `companion`: `/dashboard` in an ordinary `BrowserWindow`, `companion.ts`). The menu bar and the Office menu move between them with a single Switch (`switchMode` in `main.ts`, label `switchLabel` in `tray-model.ts`), and `officePage()` is the only place that maps a mode to a URL; a second window or a per-mode menu item breaks that. A window that is switched away from is detached (`win = undefined`), taken out of full screen (`leaveFullScreen` in `full-screen.ts`, tested in `tests/desktop-full-screen.test.ts`) and only then closed, before the other mode's window opens: opened while macOS is still on the old full-screen Space, the presenter's every-Space page window keeps that Space as an empty black one.
- `updates.ts` installs the zip named by this repository's public `latest-mac.yml` (electron-updater, Squirrel.Mac). The update has to be signed by the same Developer ID. The whole update flow is one window (`update-window.ts`); a new state is a phase in `update-view.ts` (pure, tested in `tests/desktop.test.ts`), not another `dialog`.
- A preload is `.cts` (it emits `.cjs`): sandboxed preloads can't be ES modules. `tsconfig.desktop.json` includes `*.cts`.
- Startup fails loud, never degraded. `requirements.ts` (pure, tested in `tests/startup-requirements.test.ts`) decides whether this is macOS 14+ on Apple silicon with a Pro, Max or Ultra chip; `startup.ts` reads the machine and `failStartup(failure)` shows the dialog (or, with `--startup-check`, prints to stderr), appends to `startup.log` and quits. Wording lives in `startup-failure.ts`. The native module and shared-texture code report their errors through `failStartup(nativeModuleFailure(err))` / `failStartup(sharedTextureFailure(why))`; `failStartup` throws `StartupAborted`, which `main.ts` swallows. Keep `MIN_MACOS` / `MIN_DARWIN` in step with `mac.minimumSystemVersion` in `electron-builder.yml`. `DROID_OFFICE_ALLOW_ANY_CHIP=1` skips only the chip check and exists for CI's base-chip VMs; a local run on a Mac below Pro reports the failure instead.
- `--user-data-dir=<folder>` moves `userData` and the logs, and `--startup-check` runs the gates with no window and exits. A test run of the packaged app uses both so it never touches the installed app's lock, settings or logs.
- Packaging is `electron-builder.yml`: `asar: false`, `npmRebuild: false`, arm64, hardened runtime, entitlements in `build/`. `npm run desktop` runs the checkout. `npm run package:mac` writes `release/`. `npm run build` ends with `build:native` (`native/build.mjs`: node-gyp on `native/presenter`, macOS only, Node-API so no Electron headers); `files:` ships only `native/presenter/build/Release/presenter.node`, which electron-builder signs with the app and `native.ts` loads by path. A native file loaded at runtime goes in `files:` and gets signed the same way; `release.yml` checks the presenter's architecture, minimum macOS, signature and load. Notarizing needs `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID`.
- `browser.ts` runs `droid-office browser install` on the same Helper binary at every launch, in the background and never fatal, so the Whiteboard's Chromium is downloaded on first launch and again when an update pins a new revision. The browser lives in the folder `src/server/whiteboard-browser.ts` (`browsersPath`) names, shared with source checkouts, not in `userData`. `playwright-core` ships inside the app as a normal dependency (no asar), and its bundled CLI does the download.
- The page is untrusted. Its only way to the main process is the CDP binding `__droidOfficeHost` (`input-bridge.ts`): a fixed set of messages (`lock`, `exit`, `escUp`, `editable`), each at most 512 bytes and validated, accepted only from the office's main frame in its default world at the office's origin (`trustedContext`). A new message is a new line of the allowlist, a parser branch with a test, and an entry in the guide. Validate the page's data before it reaches a file, a shell, a URL or the native module, and keep the native module and `electron` out of the page's reach.
