# Client terminal engines

**Settings → Terminal → Terminal engine** selects the renderer for the next terminal opened in this browser or Mac app. Existing terminals keep their engine and history. The saved `engine` in `droid-office.terminal` is `xterm` (default) or `ghostty`. This is not a PTY setting. The PTY host still uses `@xterm/headless` with Unicode 11. Android and laptop previews do not use wterm.

**Ghostty** uses the DOM renderer from [wterm](https://github.com/vercel-labs/wterm) and its libghostty WASM core (`@wterm/dom`, `@wterm/ghostty`, `@wterm/core`, all `0.6.0`, Apache-2.0). It does not enable WebGL2. The first opted-in view imports `wterm-runtime` and its CSS, then fetches the same-origin, Vite-hashed `ghostty-vt` WASM asset (599,627 bytes). Subsequent panes reuse the compiled module, not a live core or WASM memory. A cold xterm session requests none of these assets. If load or open fails, the same window opens xterm with one toast. The preference stays `ghostty`; the next view retries.

## Adapter contract

- `term-engine/index.ts` returns a synchronous `TerminalEngine` handle. Await `engine.term.open(host)` after `loadFonts()` and recheck the view’s lifetime before attaching. The engine opens in an inert root so no pane steals focus. It waits for the modal's finite opening animation before measuring cell advances. `proposeDimensions()` only reads layout; `resize(cols, rows)` applies the size the office negotiates. Changes Log adopts the shared PTY size, even when its font changes.
- `term-engine/wterm.ts` supplies the `ClientTerminal` write, reset, options, modes, input, viewport and lifecycle contract. Ghostty parses synchronously. Ordered microtask completion includes the empty write that `TerminalMirror` uses to drain old data before resizing and replaying a snapshot. Snapshot reset uses RIS, clears history, selection and search, and reapplies the width policy. Dispose invalidates pending callbacks and releases the DOM and core separately, even if the view closes while loading.
- `term-engine/wterm-runtime.ts` is the only package runtime entry point. `WTermOptions.core` receives a public `TerminalCore` wrapper that drains and discards `getResponse()`. Window geometry replies originate in `WTerm.write()` rather than the core; the adapter gates those callbacks while writing. Changes to theme with mode 2031 enabled cannot send a reply. User input, mouse reports and focus transitions remain distinct from these display effects.
- `src/shared/vt-scanner.ts` demultiplexes streaming CSI/DCS/OSC/ESC/APC, including split sequences. Handlers run after preceding native text and newest handler first; `true` consumes, `false` observes. Reset drops unfinished input, not handlers. The shared mirror keeps its query handlers. Mode 2027 stays off across snapshot and streamed resets to approximate server widths.
- `engine.ghostty` is a `WTermAdapter`; `adapter.native` is the public `WTerm` and `adapter.core` the unmodified pane-owned `GhosttyCore` after open. Features subscribe to `onOpen((native, signal) => …)`, `onBeforeWrite(data)`, `onNativeParsed(chunk)`, `onWriteParsed()`, `onReset()`, `onResize({cols,rows})` and `onOptionChange(key)`. The lifetime signal aborts before native teardown. `onResize` fires synchronously **after** an actual size change, not on a repeated request for the same grid.
- `features.ts` keeps all existing xterm add-ons on the native xterm path. Its wterm entries are `wterm-keys.ts` (Office key policy), `wterm-scroll.ts` (navigation and scroll preferences), `wterm-graphics.ts` (shared Kitty overlay), and `wterm-links.ts` (Office link policy and `TerminalFind`). The runtime composes the `wterm-appearance.ts` display view with its response gate. Display-only changes do not modify cells read through `adapter.core`. No package internals are patched.

## Parity matrix

**Works** is measured on this adapter or in the shipped 0.6.0 renderer as indicated. **Pending** is not a claim of parity.

| Behavior | Status | Evidence or limit |
| --- | --- | --- |
| Boss Shell, Settings, fallback and retry | Works | Production Chromium trace: zero wterm requests with xterm selected. Blocking the hashed WASM kept the shell open on xterm with one toast. On retry the same saved Ghostty choice opened wterm, and the shell returned a `printf` result. Worker, Orchestrator, inline and Changes views use the same factory/fallback; see the shared-mirror tests for ordering. |
| Attach snapshots, VT replay, width, reset and drain | Works with a flag-emoji gap | Real server snapshots replay CJK, combining, ZWJ and mixed text at the server's columns. For `🇺🇸`, the server advances 2 columns and libghostty advances 4 with clustering off. No selectable Unicode 11 table. |
| Passive mirrors | Works | Chromium exercises 194 whole and split query cases, with and without shared parser suppression. Covers DSR, DA1/DA2, ESC Z, Kitty flags, mode-2031 queries/theme changes, OSC 4/10/11/12, window geometry, DECRQM, XTVERSION and DECRQSS. No bytes arrived on `onData`. Typed `k`, both paste modes, focus in/out and an SGR wheel at 1,1 did arrive. |
| Sizing and passive focus | Works | A focused sibling button remained focused through init. A fixed 61×12 grid survived a font change from 14 to 20 px and a row spacing change from 14 to 25 px. Passive fit proposals changed without mutating that grid. A paused modal animation prevented early init; post-animation measurements use the actual font, not a platform-specific constant. |
| Theme, glass, cursor and spacing | Works for host colors and metrics | Live `setThemeColors` supplies the opaque core palette; CSS supplies the transparent host ground, cursor, selection, font and **row height**. Changing only `--term-line-height` did not change a 17 px row. A+ in the real shell changed its row from 16 to 18 px. Kitty/ANSI cursor sequences remain native. |
| Minimum contrast, underline and selection | Partial | No native 4.5:1 contrast setting; Office display-only contrast and cost measurements pending. Native selection copied a 3×2 rectangle as two three-character lines. The shipped core exposes `underlineStyle` and `underlineRgb`. |
| Ordinary/negotiated input, Option, IME, drop and paste | Partial | Basic typing, focus and ordinary/bracketed paste pass. Native Ctrl+V emitted nothing on macOS, Option+Left emitted `CSI 1;3D`, and Ctrl+Enter emitted CR without negotiation. Office key-policy parity pending. The production shell read a dropped file with spaces in its name through the existing upload and quoted-path paste flow, at 1440×900 and 1024×700. |
| Scrollback, native scrollbar, wheel, Shift+Page and reader position | Partial | `element.scrollTop` held 153 px while history grew from 45 to 50 rows. `getScrollbackCount`/`getScrollbackDiscardedCount` distinguish growth from eviction. Shift+Page Up/Down emitted modified page-key bytes natively; Office navigation, wheel tuning and settling pending. |
| HTTP(S), OSC 8, workspace paths, jump to search hit | Partial | Native OSC 8 HTTPS made an anchor; bare HTTPS did not. A `file:` URI survived in `CellData.linkUri` but did not become an anchor. Native search found and scrolled to a unique retained row. Office click/hover policy, path resolution and `fromEnd` hit selection pending. |
| Direct images, `U=1`, animation and expand viewer | Pending | Native 1×1 RGBA produced one placement. `U=1` added image storage but no placement; adding a frame did not advance the graphics generation. The office disables native image storage and uses one shared overlay for all image types. `trackPosition` retained an anchor across history and width resize but returned null after reset. The core permits 64 simultaneous handles **shared with other consumers**: if the next anchor (at latest the 65th) cannot be tracked, omit it rather than guessing a row. |
| Hidden panes, Thread and synchronized output | Works | The DOM renderer is demand-driven. In the native spike it scheduled 0 animation frames during one idle second. A paused pane parsed 6 characters with no DOM change and painted them after resume. DEC mode 2026 held intermediate output until release. Thread/Changes switches and off-screen panes pause painting; the mirror still owns attach/detach. |
| Close/reopen and lifetime | Works | After 30 browser open/close cycles followed by GC, 0 live adapters, 0 native terminals and 0 bytes of pane WASM remained. `WTerm.destroy()` does not own an injected core; the adapter also calls `GhosttyCore.dispose()`. |

Regression entry points: `tests/wterm-foundation.test.ts`, `tests/terminal-engine-{browser,parity}.test.ts`, `tests/terminal-scanner.test.ts`, `tests/terminal-prefs.test.ts` and the existing mirror/resize/input suites. New search UI, prompt jumping, Thread-to-TTY links and exit badges are follow-ups, not part of selecting an engine.
