# Client terminal engines

**Settings → Terminal → Terminal engine** selects the renderer for the next terminal opened in this browser or Mac app. Existing terminals keep their engine and history. The preference is `engine` in `droid-office.terminal`; absent, invalid or reset settings choose **xterm**. It is not a PTY setting. The server continues to run `@xterm/headless` with Unicode 11, Android continues to use xterm, and laptop/Info previews continue to draw server screen frames.

The alternative is [ghostty-web](https://github.com/coder/ghostty-web) `0.4.0-next.25.g835eb27` (MIT). A Ghostty view dynamically imports the client and loads its exported `.wasm` as a same-origin Vite asset via `Ghostty.load(url)`. Each pane owns its own WASM memory. Both Vite dev and the office's static server serve the binary; the Mac window uses that same built client. Choosing xterm does not fetch either asset.

## Integration contract

- `src/client/term-engine/index.ts`: `createTerminalEngine(options, name)` returns the window's synchronous ownership handle. Use `engine.term` (`ClientTerminal`, contract in `types.ts`) for writes, reset, resizing and input. Await `term.open(host)` **and recheck that the window is alive before attaching**. `engine.proposeDimensions()` is passive; only the office negotiates PTY size. `dispose()` is safe while Ghostty is loading.
- `features.ts`: `attachEngineFeatures(engine, images?, paths?)` installs optional engine-specific behavior. `engine.xterm` is the unmodified native xterm for the existing add-ons. `engine.ghostty` is the `GhosttyAdapter`; its `.native` is the public Ghostty `Terminal` after open. `ghostty.onOpen((native, lifetime) => …)` installs DOM features on the opened instance; its `AbortSignal` fires before disposal. Use public `renderer`, `wasmTerm`, buffer, and event APIs, not xterm internals or patched Ghostty methods.
- `src/shared/vt-scanner.ts`: `VtScanner` is a stateful, synchronous parser-hook adapter, not a second screen emulator. CSI, DCS, OSC, ESC and APC may cross writes; the last registered handler runs first. Returning `true` consumes the sequence; `false` observes it. Previous output is parsed before the callback. `reset()` drops unfinished input, not registrations. A Kitty APC (`ESC _ G` or `C1 APC G`) accepts BEL or ST and up to 16 Mi UTF-16 code units after `G`, excluding the terminator, like xterm’s Kitty splitter. Other unfinished sequences retain the 8 Mi limit. Oversized sequences are discarded through their terminator.
- `term-mirror.ts` owns ordering, passive query suppression, visibility, resnapshot and focus deduplication for both engines. Ghostty's `onWriteParsed` fires after its synchronous parser; write callbacks run on a microtask, including the empty drain before a snapshot. `GhosttyAdapter.input()` requests user input, not local echo. Its key filter translates xterm's “true = continue” to Ghostty's “true = handled.” Keydown uses the native callback. The same view handler receives real keyup (Kitty release reports) and keypress (swallowing a replacement key's follow-up) in capture on the terminal root. Returning false cancels that phase before native handling. Neither phase is synthesized, and disposal removes both listeners.


### Feature ownership

Each feature attaches once to `engine.ghostty`, including on the read-only log. Implementations and their tests belong to that feature; the engine glue and UI callers stay shared. Keep imports of `ghostty-web` type-only here: its runtime and WASM belong in the lazy factory.

| Module in `src/client/term-engine/` | Owned integration |
| --- | --- |
| `ghostty-keys.ts` | `attachGhosttyKeys(adapter).keyAction(event, csiEnter)` returns `default`, `swallow` or `send`. The view handles its own shortcuts first and sends the replacement only once. Read `adapter.options.macOptionIsMeta`; track negotiated Kitty modes through parser/reset hooks. The opened native instance exposes `options.ghostty.createKeyEncoder()`. |
| `ghostty-graphics.ts` | `attachGhosttyGraphics(adapter, images?)` handles APC, placements, overlays and the existing `images.onExpandImage` viewer. No expand callback on Changes Log. Register stream handlers before open; mount DOM and observers via `onOpen`. |
| `ghostty-scroll.ts` | `attachGhosttyScroll(adapter)` returns `handleKey(event)` (called after keyboard handling) and `snap()` (called after an immediate scroll). Own wheel/trackpad, scrollbar, page-key and reading-position behavior. `onBeforeWrite` observes native viewport state before output and `onWriteParsed` after it; `onData` includes keyboard, paste and focus reports. `scrollSensitivity`, `smoothScrollDuration` and `lineHeight` are available even when not mapped to native options. |
| `ghostty-links.ts` | `attachGhosttyLinks(adapter, paths?).find(hit)` scrolls/highlights a search hit and returns `undefined` or a user-facing warning. This module also owns the native click guard, `ghosttyTheme(theme)` (open and live), and glass. `paths?.providePathLinks(row, readLine, reply)` shares the office resolver, `paths?.linkHandler` the OSC 8 policy. `row` and cell coordinates are one-based. No path or link activation on the read-only log. |

`GhosttyAdapter.onOpen` passes the public native terminal and its `AbortSignal`. Use `native.renderer.getMetrics()`/`getCanvas()` for geometry, `native.getViewportY()` for its fractional offset from the bottom, and `adapter.redraw()` to force a redraw. Pre-open `adapter.options` includes the original theme and all office preferences. `onOptionChange(key)` fires after assignment (including unsupported native options), and `onReset()` fires before snapshot reset. Parser callbacks see prior VT output; `onBeforeWrite(data)`/`onWriteParsed()` bracket the complete write, including empty drains. Unsubscribe any external events/timers when the lifetime signal aborts.

## Parity by behavior

**Works** means implemented for Ghostty. **To port** identifies the owner module or integration seam. **Gap** means the pinned public API does not expose what xterm uses; it does not imply that the server or Android changed.

| xterm behavior | Ghostty | Detail |
| --- | --- | --- |
| Worker and Orchestrator Raw TTY window; Boss Shell; independent dashboard panes | Works | Same worker/shell attach, snapshot, input, close and detach paths. Thread views remain separate, non-streaming views. |
| Changes → Log | Works | Read-only, fixed PTY dimensions, steady cursor; `T` switches views. No keyboard input is sent. |
| Snapshot reset, ordered pending data, reconnect, stale generation rejection and bounded resnapshot | Works | Shared `TerminalMirror`, including empty writes; reset in place with RIS and clear history so input and selection stay bound to the same core. |
| Multiple viewers: adopt shared size without claiming it, refit on local pane/font resize or typing, ignore stale acknowledgements | Works | Public `FitAddon.proposeDimensions`, same 20–400 column and 5–200 row bounds. No second resize observer in the engine. |
| Hidden following pane detaches and rehydrates; scrolled reader stays attached | Works | Calculate top-of-viewport from history length minus native offset from the bottom, not Ghostty's placeholder `buffer.baseY`/`viewportY`. See streamed-output difference below. |
| Focus on explicit activation only; passive pane/log does not steal focus | Works | Isolate upstream's immediate and delayed focus on open. DECSET 1004 reports do not duplicate or claim PTY sizing. |
| Passive device/status, window, color, keyboard and DCS queries | Works | Existing `suppressMirrorQueries` handlers run before Ghostty parses the query. The PTY host remains the responder. |
| PTY input, IME/text entry, native selection/copy, ordinary and bracketed paste | Works | Native input handler and selection manager; guest/read-only, disconnected and snapshot-loading input gates remain at the view boundary. |
| Drop files or paste screenshots as quoted PTY paths, with upload limits and offline guards | Works | Engine-independent upload/paste path. |
| Esc to program, Shift+Esc/Ctrl+] to leave; host modal and terminal-cycling shortcuts | Works | Shared UI key handling; modal focus, cycle ordering (including the shell), worker state and navigation are unchanged. |
| Cursor block/bar/underline, blink preference, live font family/size and A−/A+ | Works | Mapped native options; open after the shared font load. Log overrides blink. |
| Initial foreground, cursor, selection and ANSI palette; SGR, alternate screen, CJK and combining marks | Works | Ghostty VT parser and canvas; supports grapheme clusters rather than Unicode 11 cell widths. |
| Exact Unicode 11 cursor alignment for complex emoji on attach | Gap | No selectable xterm Unicode 11 width provider. Measured `👩‍💻`: server column 4 vs Ghostty 2 (zero-based); `A漢é👩‍💻!`: 9 vs 7. `漢` and `é` alone agree (2 and 1). Later absolute cursor movements still apply. |
| Theme changes on open terminals | Works / gap | Public `renderer.setTheme` and forced redraw update renderer colors (cursor and selection); the WASM core resolves cell foreground/background to RGB at construction and exposes no palette setter. OSC 10/11 assignments are not implemented by this build. Reopen for all cell colors. |
| Companion glass/transparency | To port: `term-theme.ts`, renderer | The adapter uses an opaque ground. `allowTransparency` is not a working transparent-cell rendering contract. |
| Minimum contrast (4.5:1) and compact/default/relaxed line spacing | Gap | No `minimumContrastRatio`, `lineHeight` or public adjustable row metrics. |
| Droid Ctrl+Enter/Shift+Enter, normal shell Enter, Kitty progressive keyboard flags, per-buffer push/pop, modifier/repeat/release handling | Works | `ghostty-keys.ts` uses the same `KittyKeyboardState` and `encodeKittyKey` as xterm. It tracks separate main/alternate stacks, resets on RIS or snapshot, and leaves query replies to the PTY host. Both real browser engines produced the expected press/repeat/release bytes. |
| Mac Option as Meta vs layout characters; word navigation/deletion | Works | The live Option preference selects ESC plus the base key (Meta) or the layout character. Option+Arrow and Option+Backspace/Delete retain word navigation/deletion in either setting. Dead keys and IME composition commit text once; Cmd copy/paste remain host actions. The real-shell comparison matched all 22 byte groups across engines. |
| Kitty APC graphics transmission, probes, chunked images, placement/deletion/replay, placeholder diacritics, clipping and expand viewer | To port: `term-kitty.ts` | Public APC scanner hook, core grapheme access and canvas; do not assume xterm markers, DOM rows or decorations exist. |
| Search finds a logical line, scrolls to it, follows reflow and highlights it temporarily | To port / gap: search in `ui/terminal.ts` | Native scroll is available. No marker, stable line ID, trim count, reflow event or decoration; history length alone cannot distinguish trimming from no movement. No fake markers. |
| Cmd/Ctrl-click HTTP(S), OSC 8 policy, workspace path detection including soft wraps and wide cells, local open/reveal vs remote preview | To port: `ui/terminal-path-links.ts` | Built-in activation is gated off, including on the watch-only log. Use public link/grapheme APIs and office URI validation; built-in providers do not implement this policy. The buffer API can lose empty cells, multi-codepoint text and scrollback wrap metadata. |
| Live scroll speed, Option fast scroll, precise trackpad momentum, wheel-notch glide, row settling and held-thumb behavior | Works | Precise deltas move the native viewport directly. Physical notches glide by 50 CSS pixels before sensitivity scaling. The native thumb does not settle until released. |
| Shift+Page Up/Down accumulation, preserving the reader during output, typing and pasting snap to bottom | Works / gap at capped history | Pages accumulate from the current target. The real shell kept row 451 at the top while 50 lines arrived. Once history is capped there is no public trim count or stable row ID to preserve the same content across eviction. |
| Fractional text painting and matching selection, cursor, link, image and highlight positions | Gap | Fractional viewport offsets are public but sub-row painting and overscan are not: text pixels at offsets 81.25 and 81.75 were identical and changed at 82. An overlay cannot make the underlying canvas paint between rows. |
| Alternate-screen and mouse-reporting wheel input | Works | Normal history, alternate-screen arrows and application mouse input use separate paths. `less` scrolled in both engines; a real PTY received exactly one identical SGR wheel report for cell 1,1 in each. |
| Neutral 3px overlay thumb appears for user scroll only, hidden during typing/streaming or with no history | Gap | The native draggable scrollbar has no public styling or independent visibility API. Adding the xterm overlay would leave two drag targets. |
| Idle render scheduling and fractional-DPR cell edges | Gap | No public suspend/resume or dirty-frame scheduler. Over 60 animation frames the native renderer made 3,000 line draws reading 50 rows of history, 61 at the prompt and 60 with the pane hidden. The public renderer also has no fractional-DPR edge control. |
| XTPUSHSGR / XTPOPSGR | Gap | Tested on this binary: after red → push → green → pop, the third cell is still green. The core reports both actions unimplemented. |

Regression coverage: `tests/terminal-engine-{browser,keys,parity,scroll}.test.ts`, `terminal-scanner.test.ts`, `terminal-prefs.test.ts`, `terminal-{resize,background,cycle,paths,pixel-scroll,scrollbar,kitty-typing}.test.ts`, `kitty{,-expand}.test.ts`, `term-keys.test.ts`, and `scrollbar-styles.test.ts`. The xterm-only suites are not evidence of Ghostty parity for rows marked **to port**.
