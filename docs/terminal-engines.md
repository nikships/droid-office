# Web, Mac and Android terminals

Worker windows, inline panes, Boss Shell, Changes Log, `/dashboard` and Android Raw TTY use [wterm](https://github.com/vercel-labs/wterm)’s DOM renderer and libghostty WASM (`@wterm/dom`, `@wterm/ghostty` and `@wterm/core` 0.6.0, Apache-2.0). Android loads its own feature list and package-local assets in a WebView. The server mirror still uses `@xterm/headless`, `@xterm/addon-serialize` and `@xterm/addon-unicode11`: wterm 0.6.0 cannot provide the complete screen snapshots needed for a reconnect. Mode 2027 remains off in clients for compatibility with that mirror. The 3D screens draw compact server previews, not another interactive terminal instance.

Both web entry points warm the runtime when idle. Concurrent loads of the same hashed `ghostty-vt` URL share the package’s download and compiled module; each pane owns and disposes its own core and memory. The binary is 599,627 bytes. If opening fails, the pane stays open with an inline **Retry** button and one toast. It sends no input while unavailable, and does not retry automatically. Settings control presentation and input, not the renderer. Older saved engine values are ignored.

Android Raw TTY packages the JavaScript, CSS and WASM inside the APK. The native input connection owns Direct input. On the stock Android 9 (API 28) emulator, Chrome WebView 66 fetched all 599,627 WASM bytes with the correct MIME type, but the embedder disallowed WebAssembly compilation. Raw TTY shows **Unavailable** on that provider; there is no alternate renderer. See [the Android app guide](../android/README.md) for Phone and Desktop sizing, input and navigation.

A replacement snapshot closes Find on web and Mac. On Android, a replacement snapshot on an existing renderer closes Find, clears the query and keeps the reading position when the line is still in history. A fresh Android renderer can rerun a preserved query.

## Adapter contract

- Each window owns a `WTermAdapter`. Await `openTerminalRenderer(term, host, alive)` after `loadFonts()` and recheck the view’s lifetime before attaching. The engine opens in an inert root so no pane steals focus. Mount, attach and first paint do not wait for the opening animation. Synchronous `WTerm.fit()` metric probes counter-scale ancestor transforms (collapsing only horizontal width/padding), so virtual spacers and tail-follow use unscaled CSS pixels. Only pointer hit testing waits for the opening transform to finish (240 ms dashboard, 160 ms modal), when a single metrics refresh restores the settled cell geometry. A click on the concealed terminal still focuses its keyboard. The first visible grid contains the negotiated snapshot; a subsequent snapshot keeps the previous grid visible until the replacement paints.
- A resize observer caches whole cells from the scrollport and native font probe. A classic scrollbar takes its actual width; an overlay scrollbar takes none. Typing in a shared pane can claim the cached size without measuring layout. Pane and sidebar transitions, window resizing and splitter drags keep the old grid until the box settles, then publish only a changed size. A text-size step paints the new font and fitted grid together. Quick successive steps keep the previous layout until the final size is ready; the program's own redraws are not held. Input bytes do not wait for a size claim. A shrinking viewport keeps tail followers at the bottom and leaves history readers in place. Changes Log adopts the shared PTY size, even when its font changes.
- `term-engine/wterm.ts` supplies the terminal write, reset, options, modes, input, viewport and lifecycle contract. Ghostty parses synchronously. Ordered microtask completion includes the empty write that `TerminalMirror` uses to drain old data before resizing and replaying a snapshot. Snapshot reset uses RIS, clears history, selection and search, and reapplies the width policy. Dispose invalidates pending callbacks and releases the DOM and core separately, even if the view closes while loading.
- `term-engine/wterm-core.ts` loads the public core, installs the supplied feature list after initialization and has no web feature or CSS import. `wterm-runtime.ts` supplies the web/Mac feature list. Both web entries load the terminal styles in the base stylesheet, so Retry does not depend on a failed lazy CSS preload. `WTermOptions.core` receives a public `TerminalCore` wrapper that drains and discards `getResponse()`. Window geometry replies originate in `WTerm.write()` rather than the core; the adapter gates those callbacks while writing. Changes to theme with mode 2031 enabled cannot send a reply. User input, mouse reports and focus transitions remain distinct from these display effects.
- `src/shared/vt-scanner.ts` demultiplexes streaming CSI/DCS/OSC/ESC/APC, including split sequences. Handlers run after preceding native text and newest handler first; `true` consumes, `false` observes. Reset drops unfinished input, not handlers. The shared mirror keeps its query handlers. Mode 2027 stays off across snapshot and streamed resets to approximate server widths.
- `adapter.native` is the public `WTerm` and `adapter.core` the unmodified pane-owned `GhosttyCore` after open. Features subscribe to `onOpen((native, signal) => …)`, `onBeforeWrite(data)`, `onNativeParsed(chunk)`, `onWriteParsed()`, `onReset()`, `onResize({cols,rows})` and `onOptionChange(key)`. The lifetime signal aborts before native teardown. `onResize` fires synchronously **after** an actual size change, not on a repeated request for the same grid.
- The runtime installs `wterm-keys.ts` (Office key policy), `wterm-scroll.ts` (navigation and scroll preferences), `wterm-graphics.ts` (shared Kitty overlay), and `wterm-links.ts` (Office link policy and `TerminalFind`). The runtime composes the `wterm-appearance.ts` display view with its response gate. Display-only changes do not modify cells read through `adapter.core`. No package internals are patched.

Web and Mac terminals keep the invisible keyboard input out of the history's scroll range after ED3, resize or snapshot replay ([wterm #245](https://github.com/vercel-labs/wterm/issues/245)). A visible IME preedit remains at the cursor. The viewport uses whole CSS pixels with one pixel of bottom inset available for rounding: keyboard input and echo renders reach the same native end even at fractional browser zoom ([wterm #293](https://github.com/vercel-labs/wterm/issues/293)). These adjustments do not align reader positions to rows. Output, wheel routing and Find treat a gap smaller than one CSS pixel (or one device pixel, if larger) as the tail, without moving the scrollport to measure it.

## Find, prompts and clipboard

In a web or Mac terminal, use **Find** (or the magnifying glass button next to the other tools in the web/Mac companion pane header), Cmd+F on Apple devices, or Ctrl+Shift+F elsewhere. Enter and Shift+Enter step through native scrollback matches; Escape closes Find and restores the reader position. `window.office.readTerminal()` reads only visible, already-open web terminals, without attaching to the PTY.

When a shell emits OSC 133 marks, the prompt chip shows its current phase or exit status. Its arrows and Ctrl+Shift+[ / Ctrl+Shift+] move between retained prompts. Reattaching restores text, not old marks. **Settings → Terminal → Shell prompt integration** controls the default zsh hooks for newly started Boss Shell and shell workers across all floors. Alt-drag selects a rectangle; use Shift+Alt-drag when the application tracks the mouse.

A live, writable owner's terminal forwards supported OSC 52 clipboard writes to the platform. The browser decides permission, including whether to ask on the first write. The office never reads the clipboard for an OSC query, retries a denied write, or applies writes while parsing a snapshot or its queued output. A write request that starts in replay stays ineligible even when its terminator arrives live. A guest, read-only or disconnected terminal cannot write. A local OSC 7 directory report can help resolve relative file links, but cannot add a workspace root or grant access.

## Web and Mac parity matrix

These results use the shipped 0.6.0 core in Chromium. Where the PTY protocol or public core API limits parity, the table describes what the user sees.

| Behavior | Status | Evidence or limit |
| --- | --- | --- |
| Open failure and retry | Same pane | The renderer opens before the window attaches to a PTY. Explicit retry reuses the existing host and its bound input and mirror handlers. |
| Attach snapshots, VT replay, width, reset and drain | Works with a flag-emoji gap | Real server snapshots replay CJK, combining, ZWJ and mixed text at the server's columns. For `🇺🇸`, the server advances 2 columns and libghostty advances 4 with clustering off. No selectable Unicode 11 table. |
| Passive mirrors | Works | Chromium exercises 194 whole and split query cases, with and without shared parser suppression. Covers DSR, DA1/DA2, ESC Z, Kitty flags, mode-2031 queries/theme changes, OSC 4/10/11/12, window geometry, DECRQM, XTVERSION and DECRQSS. No bytes arrived on `onData`. Typed `k`, both paste modes, focus in/out and an SGR wheel at 1,1 did arrive. |
| Sizing and passive focus | Works | A focused sibling button remained focused through init. A fixed 61×12 grid survived a font change from 14 to 20 px and a line-spacing change from 1 to 1.25. Passive fit proposals changed without mutating that grid. A click during the opening scale sends no cell report; a settled click reports the painted cell. |
| Theme, glass, cursor and spacing | Matches stored preferences | `setThemeColors` receives opaque RGB; the CSS background keeps the alpha from `#rrggbbaa`. The adapter measures the actual font ascent and descent and applies line spacing in device pixels. Grid width is independent of the current PTY columns. At DPR 1, 14 px Geist Mono with 1.1 spacing paints a 19 px row. Kitty/ANSI cursor sequences remain native. |
| Application colors, cursor and selection | Native ink | Wterm paints application RGB, dim text, underline styles and block-cursor glyphs. The host sets the palette and selection tint. Partial blocks expose the pane and shades blend with it unless the program sets a background. Reverse video and block cursors keep opaque ground-colored ink. |
| Keyboard, selection, drop and paste | Native wterm | Ghostty tracks Kitty and modifyOtherKeys modes. Wterm encodes delivered presses, repeats and releases. Escape interrupts without taking the next Tab or Shift+Tab from the program. Cmd+A or Ctrl+Shift+A starts one native history selection. Escape cancels it even before text is available to copy. Only Escape that cleared a selection allows the next Tab to leave the terminal. Selected text does not intercept Mac Ctrl+C; Mac Ctrl+V goes to the program ([wterm #267](https://github.com/vercel-labs/wterm/issues/267)). Option can send Meta or layout text. Before an agent negotiates Kitty, Ctrl+Enter still queues. Unnegotiated shells submit Shift+Enter as Return. Browser paste and quoted uploaded paths preserve LF and strip embedded ESC in bracketed mode; without brackets, each LF or CRLF becomes one Return. Focus reports on actual transitions preserve the reader's scroll position. |
| Scrollback, scrollbar and wheel | Works | The browser scrolls normal-screen history. A wheel gesture or scrollbar drag can stop between rows, even two pixels from the end while output streams. A short Changes Log can scroll its shared grid even after history is cleared. Shift+Page moves one viewport with one row of overlap. Slow/Fast and Option+wheel scale the wheel distance. At the history cap both engines kept `row 36` visible through six evictions. Typing or pasting resumes tail-follow. In the alternate screen the wheel sends application or normal cursor arrows, or the negotiated mouse report instead of scrolling history. Sub-row motion accumulates before a program receives a mouse-wheel report; a reader above the tail keeps scrolling history. |
| Mouse reports over the string PTY | ASCII boundary for default encoding | In legacy binary encoding, cell coordinates 1–95 fit in ASCII. The adapter forwards a report only if **every** byte is below 128; otherwise it drops the whole report instead of changing the byte sequence during UTF-8 transport. SGR cell/pixel coordinates are decimal strings and unaffected. The earlier xterm client did not subscribe to `onBinary`. |
| SGR-pixel origin (1016) | One-pixel difference | Native press, move and release report one-based pixels; the previous xterm client reported zero-based pixels. |
| X10 press-only tracking (DECSET 9) | Not supported | The core does not expose this tracking mode, so a press does not produce an X10 report. Modern cell-based SGR tracking is unaffected. |
| HTTP(S), OSC 8, workspace paths and search | Office modifier-click | Native OSC 8 anchors stay disabled so program output cannot take keyboard focus, Enter or Tab. Cmd/Ctrl-click opens a web link or a validated workspace target. Pointer lookup skips incomplete logical lines and lines over 16,384 cells. Changes Log and Android do not open links. Global search honors `fromEnd` and temporarily highlights the full match. |
| Kitty direct images, `U=1`, animation and expand viewer | Works with placement limits | The Office overlay shares its fixtures with an xterm test oracle. Chromium compares split/compressed RGB, RGBA and PNG, animation frames, deletion, clipping, history, fractional scroll, raw placeholder cells and the expand viewer. A palette-indexed placeholder ID and an equivalent resolved truecolor value are indistinguishable in wterm's public cells. When a direct placement's row cannot be proven after a line edit, clear or scrolling-region change, the overlay drops it instead of drawing it on a different row. |
| Direct placement lifetime | Bounded to 60 graphics handles | Each core has 64 tracked positions. Graphics reserves four for links/find. Excess direct placements remain invisible, without changing cursor movement. Existing normal-screen images return after DEC 47/1047/1049 if history and geometry are intact, even after ED3 in the alternate screen. Resize, DEC 80/132-column changes and uncertain transitions invalidate saved positions. Direct (non-placeholder) images placed while a program is in the alternate screen are **not drawn**, just as in the previous xterm client: its overlay collected direct placements only on the normal screen. Both renderers draw `U=1` placeholders in the alternate screen. Partial margins also lack a trustworthy normal-screen anchor in wterm. |
| Hidden panes, Thread and synchronized output | Works | A hidden reader stayed at history row 30 and moved to row 24 after six evictions, just as when visible. In the mounted agent UI, switching Thread → Raw restored the same labeled line after a fresh snapshot trimmed seven rows. `saveReader()` captures a visible historical line and its neighbor, then restores the nearest matching row after the latest snapshot paints. A second snapshot before paint keeps this position pending; new navigation supersedes it, and later resyncs do not apply it twice. Changes Log stays attached; switching back reveals its current reader. At the tail both views follow output. Paused wterm parses without painting, paints again on resume, and honors synchronized output (mode 2026). |
| Close/reopen and lifetime | Works | After 30 browser open/close cycles followed by GC, 0 live adapters, 0 native terminals and 0 bytes of pane WASM remained. `WTerm.destroy()` does not own an injected core; the adapter also calls `GhosttyCore.dispose()`. |

## Streaming CPU cost

In 20 matched-grid trials, streaming output used more CPU with wterm (`71f8c68d`) than with xterm (`7c1044fd`). With one pane, median CPU rose from 32.93% to 44.25% of one core (+34% relative). With three panes, it rose from 29.09% to 37.23% (+28%). Wterm used more CPU in all five pairs for each pane count. Idle and Thread-view differences were within measurement noise; frame rate was unchanged.
