# Models and prompts

## Choosing a model

Every worker and board agent is a Droid session: the office runs the [Droid CLI](https://docs.factory.ai/cli/getting-started/quickstart) (`--agent`, default `droid`; `DROID_OFFICE_AGENT` changes it), passing each one its prompt and resuming a saved session with `droid --resume <session-id>`. `--agent-args` adds extra flags for Droid, e.g. `--agent-args "--auto medium"`.

The hire, hand-off and Subagents windows list every model droid can run, the same list as droid's own model picker: the office asks `droid exec` for it in JSON-RPC mode (`droid.list_models`, which starts no session and calls no model) and caches it for a minute, falling back to the models your own `~/.factory/settings.json` names (every custom model, plus your session default and favorites) when droid can't answer. Each model field is a searchable picker rather than the system dropdown: type to filter by name, id or provider, use the chips to show only your own models or one provider, and read the credit multiplier on every row. The last four picks sit on top as **Recent**. Your own models are grouped by the gateway that serves them (DroidProxy, OpenRouter…), Factory's by provider, with legacy ones last; disabled models are left out, and the effort list (low, medium, high, xhigh or max) offers only the efforts the picked model takes, its own default named on **Default**. Leave the model on **Default** to run the office's Default worker (below), or whatever your Droid settings say when none is set; the option names the model and effort it runs, such as **Default (Opus 5.5)**. A pick is pinned for that worker only: interactive droid has no `--model` flag, so the office writes the model and effort into that worker's own settings overlay (`.droid-office/droid-<id>.json`), merged for that process alone. It stays with the worker across resumes and never changes your Factory settings.

Set the office's **Default worker** in ⚙️ Settings → **Workers**: a model and effort for whatever nobody picks one for, like board agents. Until you set it, those start on `--agent` with Droid's own default model, as they always have. The hire and ask windows keep their own pickers and memory; a choice made there wins over the default.

The office generates `.droid-office/droid-hooks.json` and passes it as a per-process `--settings` overlay: lifecycle events report status to a token-protected loopback endpoint without editing your Factory settings or changing autonomy and approval policies. Complete login or any hook review in the worker's terminal if startup pauses. Every Droid worker also starts, and resumes, with the **Worker system prompt** added to Droid's own system prompt (`--append-system-prompt-file`). It tells the worker it's in Droid Office and what the office gives it (Droid already tells every session its folder, branch and git status): subagents are hired with `office-workers` rather than Droid's Task tool, and anything you should look at (screenshots, mockups, plans, choices) goes on the Whiteboard with `office-whiteboard`. Rewrite or empty it under **Every worker** in the prompt editor. `/model` in a worker's terminal changes its model mid-session, and the office reads the model and effort Droid's own session bookkeeping names, so the badge next to a worker shows what it really runs.

## The office's prompts

Everything the office tells a worker by itself can be rewritten in ⚙️ Settings → **Workers** → **Prompts**: the system prompt every Droid worker starts with (empty adds none; a change reaches a worker the next time its session starts or resumes), what **Hand to a worker**, **Review**, **Fix up & merge**, **Fix conflicts & merge** and **Ask a worker…** send from the issue and pull request boards, what **Commit & open PR** asks a worker from its Changes window, the three board agents' briefs, the brief written into a workspace when one task spans several repositories, the task **Have a worker set it up…** writes for a repository's worktree setup, the line **Ping a worker** types into a worker's terminal from the Whiteboard, and the instructions for the model that writes the signs over workers' heads. Each one lists its `{{placeholders}}` (the issue number, the PR's branch, and so on), which the office fills in when it sends it, and warns when one the office counts on is missing. On a GitLab floor the same prompt reads in GitLab's words: `{{site}}`, `{{cli}}`, `{{pullName}}`, `{{ref}}`, `{{read}}`, `{{checkout}}`, `{{merge}}` and the rest become GitLab, `glab`, merge request, `!12` and the `glab mr` commands, so the office's own wording is word for word what it sends on each forge. **Default** puts the office's own wording back. The Jira board's hand-off prompt isn't one of them. They're the same on every floor and kept in the office's `.droid-office/prompts.json`, with the Default worker.
